# v1.4.0 · 角色库、失败诊断与多标签同步

## 新增

### 全局角色库 / 拉群

- 角色从“群里的成员”改为独立资产，保存在 `characters/<cid>/`。
- 群只保存 `characterIds`（2–3 个），不再复制成员档案。
- 新建群可以直接从角色库勾选 2–3 个角色，也可以继续“新建角色并建群”。
- 群成员页支持从角色库拉人、移出成员；移出只解除引用，不删除角色。
- 删除仍被群引用的角色会被拒绝，并列出使用它的群。
- 改名、头像、设定只改一处，所有引用群同步显示。
- 群导出继续内嵌角色快照；导入时创建新的全局角色。

### 数据迁移

- `schemaVersion` 升到 `2`。
- 旧版 `groups/<gid>/members/<cid>/` 会在首次加载时迁移为全局角色。
- 迁移复用原成员 ID，历史消息的 `memberId` 不失效。
- 旧 `members/` 目录保留，便于回滚。

### 失败诊断

- 生成失败会写入可重放的 `notice`，刷新后仍能看到。
- 群设置显示最近一次路由的目标、旁听、方法和原因。
- 可以区分 owner 路由、模型报错、请求中断和预算停止。

### 私有记忆 UX

- 私有记忆编辑区显示字数，并支持一键清空；保存后生效。
- 导出群配置 / 角色卡勾选“包含私有”时显示醒目警告。
- Markdown 导出明确提示且实际不包含私有记忆与私人关系。

### 多标签页同步

- 以 `BroadcastChannel` 为主，`storage` 事件兜底。
- 发消息、钉住、改群 / 角色、建群、删群、导入后，其他标签页约 250 ms 内刷新。
- 正在流式生成的标签页不会被打断，等本轮结束后再同步。
- 不同标签页仍可各自查看不同的群。

## 验证

- 102 项确定性测试通过。
- `node --check client.js`、locale 285/285 对齐、`npm pack --dry-run` 通过。
- CI 在推送后自动执行同一组检查。
- 实测数据迁移：3 个角色 / 44 条消息 / 事件重放正常。

## 兼容性

- 旧版群数据会自动迁移；迁移失败保留旧数据，不静默覆盖。
- 旧消息、钉住、重写历史、导入的角色卡/群配置继续可用。
- 当前仍只支持 JSON；YAML 留待后续。
- 尚未发布到 npm；使用 GitHub Release 的预构建 tarball 安装。

## 安装

```bash
dsh plugin --profile web add "https://github.com/zhdzh-good/multi-role-groupchat/releases/download/v1.4.0/zhdzh-good-multi-role-groupchat-1.4.0.tgz"
```

安装或升级后重启 `dsh web` 并刷新页面。多标签同步需要浏览器支持 `BroadcastChannel`；不支持时会回退到 `storage` 事件。

# v1.5.0 · 失败重试与长历史分页

## 新增

### 失败重试

- 生成失败的通知持久化 `retry` 元数据（`turnId`、`memberId`、`replyIndex`、`replyTo`、`routeRole`、`attempts`、`resolved`）。
- 失败通知右侧提供「重试」按钮。
- 重试只补失败的那一条成员回应：
  - 不改写 owner 消息和已经成功的回应；
  - 同一 `turn / member / replyIndex` 已有消息时直接拒绝，避免重复；
  - 成功后原通知标记「已重试」，刷新后仍然保留；
  - 重试再次失败时，旧通知标记已重试，并生成一条新的可重试通知，`attempts` 递增。
- 预算不足与用户主动停止不提供自动重试。
- 新增 `POST /api/groupchat.retry`。

### 长历史分页

- 展开全部历史时，一次最多渲染最近 300 条。
- 顶部显示「显示更早的 N 条」，每点一次再加载 300 条。
- 避免 5000 条消息一次性进入 DOM。
- 默认聊天视图仍只显示折叠后的最近消息，首屏不受影响。

## 兼容性

- 数据格式不变，没有 `schemaVersion` 变更。
- `retry` 是 notice 的可选新增字段；旧事件日志没有该字段时照常加载，不迁移、不重写历史事件。
- 已有群、角色、消息、钉住、私有记忆、导入导出继续可用。
- 失败重试只重试失败的那一条成员回应；不会重新路由，也不会补跑失败后本应继续的旁听者或接话链。
